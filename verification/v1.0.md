## 3. Wheel install and minimum versions

**Wheel (B1).** `python -m build` produced `blackpy_gr-1.0.0rc1.tar.gz` and
`blackpy_gr-1.0.0rc1-py3-none-any.whl`; `twine check` passed both. The wheel
contains the 67 modules of `blackpy`, the 8 registry YAML files, `py.typed`
and the license; no tests, examples, `site/` or `.DS_Store` (the sdist
contains tests, docs and examples, but not `site/`, `build/`, the
specification files or `.github/`). In a fresh virtual environment
(`build/wheel-env`, Python 3.13.5) the wheel was installed (not editable),
`import blackpy` resolved to `site-packages`, `blackpy.data.load("eht/sgra")`
worked, and the quick subset, run from the repository against the installed
package: 284 passed for the first wheel (end of Part B) and **291 passed** for
the final 1.0.0rc1 wheel (160 s).

**Minimum versions (B2).** All declared lower bounds were installed together
in `build/min-env` with Python 3.10.20 (macOS arm64): jax 0.4.30, jaxlib
0.4.30, numpy 1.24.4, scipy 1.10.1, sympy 1.12, matplotlib 3.7.5, corner
2.2.3, pyyaml 6.0.3, emcee 3.1.6, dynesty 2.1.5 (ml_dtypes 0.5.4 came with
jax). The first run gave 3 failures out of 284, all in the tests, none in the
package:

1. `test_isotropic_prior` used `np.trapezoid` (NumPy >= 2.0);
2. `test_constants_match_scipy_codata` read SciPy's private CODATA 2022 table
   (SciPy >= 1.15);
3. `test_schwarzschild_orbit_quantities` asserted that no circular orbit
   exists at exactly r = 3 M (the photon orbit). There the existence condition
   f h' - h f' is 0 analytically; both JAX versions compute 2.2e-16 for it,
   but the compiled comparison inside `exists_core` returns True with JAX 0.4.30
   and False with 0.12 (different fusion). The assertion tested round-off; it
   now checks 3 M ± 1e-6 instead.

After these test fixes: 284 passed at the end of Part B, and **291 passed** with the
final 1.0.0rc1 wheel (241 s). The bounds therefore stay as declared;
lower versions were not explored. Python 3.10: JAX 0.6.2 is the last JAX for
Python 3.10 and JAX 0.7.0 requires Python >= 3.11 (PyPI metadata:
`requires_python` of each release), so 3.10 users get JAX <= 0.6.2; 3.10 stays
supported (owner decision 6). The pins are in `.github/min-requirements.txt`
for the `min-deps` CI job.

**Persistent compilation cache (optional B3 item).** Not measured; not added
to `tests/conftest.py`.

## 4. Public API, units and names (Part A)

- Public API defined (design decision 38): 16 public modules; `__all__` added
  to `constants`, `errors`, `qnm`, `thermo`, `metric.interpolated`.
  **The specification's statement that `blackpy.disk` has no `__all__` is
  wrong**: it had one in 0.3 (with the four intended names).
- Deprecated aliases (A2): six names, served by a module `__getattr__`, removed
  from `__all__` and from the user-facing documentation.
- **Angles (A3, decision 39)**: every angle in radians, degrees carry `_deg`.
  The inference parameter `inclination` is now `inclination_deg`
  (`inclination_deg_<source>`); the old names are accepted (with a warning) in
  priors, fixed values, `shared`/`per_source`, `Fit.log_likelihood` and
  `goodness_of_fit` keywords, forecast fiducial points, `FitResult[...]`,
  `simulate_shadow_dataset(inclination=...)` and format-0 bundles. The registry
  keeps degrees; the one M87\* entry without a unit (`inclination.other_values[0]`)
  got `unit: deg` (no number changed). The radian guard was added to
  `shadow_contour`, `shadow_observables`, `shadow_radius` (through
  `shadow_observables`), `deviation_from_circularity`, `photon_region`,
  `shadow_in_plasma` and `plot.shadow`. **No opposite guard on
  `inclination_deg`**: a test such as "the whole prior lies below 1.6" would
  reject legitimate nearly face-on priors, so the name is relied upon.
- **Unit table**: section 12 of the user guide. Writing it found no docstring
  with a wrong unit; units were added where only implied. Inconsistencies kept
  for compatibility (recorded as 2.0 decisions in `TO_DO.md`): `mass` versus
  `mass_msun`; `distance_kpc` versus `distance_lens_kpc`; `n` (contour points,
  quadrature nodes, predictive draws); positional `r_obs` in the shadow
  functions but keyword-only in `plot.shadow`. `n_scan` is used consistently.
- **Errors (A4)**: `ForecastWarning` moved to `blackpy.errors` (still
  importable from `blackpy.infer` and `blackpy.infer.forecast`);
  `RegistryError` moved there too (still in `blackpy.data`; now also a
  `BlackPyError`, still a `ValueError`); `blackpy.errors` has `__all__` and is
  in `docs/api.md`.
- **Messages (A5)**: no source file names a repository file; stubs point to
  the hosted roadmap page (`blackpy._links`). Registry YAML files keep their
  provenance references, updated to `verification/v0.2.md`.
- **Bundles (A6)**: `bundle_format: 1` (decision 40), fixtures of formats 0 and 1.
- **Typing and reference (A7)**: `py.typed` in the wheel; `docs/api.md` lists
  every public name (86 of the names in the 1.0 snapshot were not on the 0.3
  page, counting `blackpy.errors`, the constants, the modules that gained
  `__all__` and the three new plot helpers; among them every result type and
  both catalogues; the specification estimated about 45); `blackpy._numerics` moved to
  "Internals (not part of the public API)".
- **Small fix found while writing the guide**: LaTeX labels of per-source
  parameters did not escape underscores (`M_{\rm src_a}` rendered `src` with a
  subscript); fixed.

## 7. Known limitations

1. **No human verification of the data** (unchanged): every registry number is
   provisional. `TO_DO.md`, section 2, lists every value with its paper and
   location (generated by `scripts/registry_checklist.py`).
2. **The 1.0 workflows have never run.** The workflows (`ci.yml` with the new
   `wheel` and `min-deps` jobs, `full.yml`, `examples.yml`, `docs.yml`,
   `release.yml`) were checked as YAML only. On GitHub, the owner reports, the
   former `full` job of `ci.yml` timed out after 60 minutes and macOS runners were
   not available. The full suite is therefore a separate workflow (`full.yml`),
   run on manual dispatch only, with a 180-minute timeout; its weekly schedule is
   commented out until the repository is public (`TO_DO.md`, section 4). The documentation outputs were produced on macOS; a platform with
   different round-off could differ in a printed digit (the sampler outputs have
   a tolerance; exact outputs are rounded to 4 to 8 significant digits).
3. **The 1.0 code has not run on Windows** (the baseline in section 1 is for
   the pre-1.0 code).
4. `strong_field_observables(dataset=...)` uses registry values without an
   `UnverifiedDataWarning` (a prediction, not a fit); recommended for 1.1.
5. Minimum versions were tested only as a set and only on macOS arm64.
6. All limitations of `v0.3.md`, section 6, still apply (no new physics).

## 8. Points in the specification that I think are wrong or need a decision

1. **A1: "`blackpy.disk` has no `__all__`"**: it had one in 0.3. The modules
   that lacked one were `constants`, `errors`, `qnm`, `thermo` and
   `metric.interpolated`.
2. **A3: "Result bundles of format 0 with an `inclination` column load with the
   column renamed"**: done, but the same name also appears in the record's
   priors, parameter kinds, bases, per-source inclination records and
   diagnostics; all are renamed, otherwise a loaded result would be
   inconsistent.
3. **C1: "the outputs printed in the guide must match ... to the digits shown"**
   conflicts, for registry-dependent outputs, with the rule that tests must not
   depend on unverified registry numbers. Such outputs are marked "Output
   (registry data)" and are run but not compared. Sampler outputs are compared
   with a tolerance, because Monte Carlo chains are not bit-reproducible across
   platforms (decision 41).
4. **B2: "raise each lower bound to the lowest version that passes"**: the
   declared bounds pass, so nothing was raised; lower versions were not tried
   (they would widen the promise without need).
5. **C1, FAQ "Windows (no hard symbolic time limit)"**: correct, but the
   symbolic computations are the only place where this matters; the FAQ says so.
6. **Owner decision 8 (GitHub Pages)** needs a public repository or a paid
   plan for a private one; recorded in `TO_DO.md`.
7. **"the quick subset in about 2 minutes as before"**: 145 s on an idle
   machine with the new quick tests; moving the README/quickstart snippet test to the slow subset
   would bring it back under two minutes, but would leave the quick subset
   without any documentation test. I kept them quick.
